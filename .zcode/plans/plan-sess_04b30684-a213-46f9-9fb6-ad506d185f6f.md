## Pindahkan snapshot diskaun/cashback dari Sales Order ke Booking

**Matlamat:** Buang `custom_cashback_percent`, `custom_voucher_discount`, `custom_referral_discount` dari Sales Order. Nilai disimpan pada doctype **Booking** (app sendiri, dah ada `voucher`/`affiliate`/`pre_discount_total`). Perakaunan PE-deduction ke Marketing Expenses **kekal 100% tak berubah** — cuma lokasi storan berpindah.

### 1. Schema Booking — `booking.json`
Tambah 3 field read-only di `payment_section` (selepas `pre_discount_total`, ikut atribut field sedia ada):
- `voucher_discount` (Currency) — "Voucher Discount Amount"
- `referral_discount` (Currency) — "Referral Discount Amount"
- `manual_transfer_cashback_percent` (Percent) — "Manual Transfer Cashback Percent" (nama selaras Travel Settings)

### 2. Penulis — `api/booking_engine.py` (`confirm_booking`)
- Buang 3 baris dari `so_payload` (baris 500-501) dan cabang cashback (baris 549). **Guard akaun Marketing Expenses (541-548) dikekalkan.**
- Tambah nilai ke payload penciptaan Booking (~baris 687, sebelah `pre_discount_total`): `voucher_discount`, `referral_discount`, `manual_transfer_cashback_percent` — nilai dah dikira awal (baris 382-425), jadi tersedia masa Booking dicipta.
- Kemas kini komen (baris 379, 417). Response API (832-835) **tidak berubah** — frontend JS tidak terjejas (JS tak pernah baca fieldname SO; ia kira semula dari `get_payment_settings`).

### 3. Pembaca — helper baharu + 3 panggilan
Helper baharu di `api/so_helpers.py`, cth `_get_booking_discount_snapshot(so_name)`: baca Booking melalui `SO.custom_booking` (SO tanpa link → sifar, sama seperti tingkah lama bila field kosong). Kemudian:
- `so_helpers.py:557-565` `_get_order_discount_total()` → guna helper (ini automatik meliputi laluan settlement Stripe `_settle_order_discount_residue`)
- `portal_payment.py:522-525` → buang 3 field dari fetch; baris 607 & 612-613 guna helper (fail ini sudah import dari so_helpers)
- `stripe_checkout.py:189-191` → buang field dari fetch; `net_payable` (251-252) guna helper

### 4. Patch migrasi — `patches/v8_move_order_discount_fields_to_booking.py` (post_model_sync, daftar selepas v7 dalam patches.txt)
1. Salin nilai lama: untuk setiap SO ber-`custom_booking`, isi field Baharu Booking (hanya jika masih kosong/0). Baca medan SO dengan guard `frappe.db.has_column` (toleran site yang field dah tiada).
2. Padam ketiga-tiga Custom Field dari Sales Order (`delete_custom_field`, `ignore_missing=True`).

### 5. Yang TIDAK berubah
Mekanisma PE deduction (`_get_absorbed_order_discount`, `_build_discount_deduction_rows`, `_settle_order_discount_residue`, `_create_manual_payment_entry`), laluan B2B (`additional_discount_percentage`), JS frontend, API response, DocType Layout SO (disahkan tak rujuk ketiga-tiga field).
