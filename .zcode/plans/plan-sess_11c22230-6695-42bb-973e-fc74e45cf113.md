## Part A — Passport copy display (#3)

Paparkan gambar passport yang sudah di-upload pada card "Passport Copy" (docs.html + guest page). Sekarang cuma ada nota teks "✓ on file".

**A1. Slot payload** — `api/portal_booking.py` `get_booking_data` (slot dict ~:166-167): tambah `"passport_image": raw.passport_image or ""` dan `"visa_photo": raw.visa_photo or ""` (URL fail) selain boolean sedia. SQL dah SELECT kedua-dua (`:104-105`).

**A2. File-serving endpoint** — fail disimpan `is_private:1` pada Traveller; customer (tiada role Traveller) & guest (no session) tak boleh akses `/private/files/...` terus. Tambah di `api/portal_traveller.py`:
- `get_slot_file(booking_number, slot_name, field)` — `@frappe.whitelist()`; session-validated (via `_get_customer` + booking/slot ownership macam `save_booking_traveller`); baca `Traveller.<field>` file_url, pulangkan `{"data_url": "data:<mime>;base64,..."}` (base64 — konsisten dgn corak filedata sedia, elak komplikasi binary response).
- `get_guest_file(token, field)` — `@frappe.whitelist(allow_guest=True)`; token-validated; sama streaming.
- Helper `_serve_traveller_file(traveller_name, field)` dikongsi (read File via `frappe.get_doc("File", {"file_url": ...})`, `get_content()`, base64-encode).

**A3. Form partial preview** — dalam passport card (docs.html `:126-129`): gantikan/augment gambar CONTOH dengan `<img id="passport-preview" style="display:none">` yang tunjuk gambar sebenar bila `has_passport`; contoh kekal sebagai placeholder bila tiada. (Bentuk partial — lihat Part B3.)

**A4. JS** — `portal_traveller_page.js` `_loadTravellerForm` (~:485): bila `slot.has_passport`, fetch `get_slot_file` (atau `get_guest_file` bila guest mode) dan set `passport-preview.src`; tunjuk/hide accordingly.

## Part B — Guest passport link (#5)

Guest (co-traveller, no login) isi maklumat penuh mereka sendiri melalui token link.

**B1. Schema** — `booking_reservation.json`: tambah section "Guest Passport Link" dengan 3 field read_only:
- `passport_link_token` (Data, len 32, search_index)
- `passport_link_email` (Data, options Email)
- `passport_link_expires_on` (Datetime)
Token = `frappe.generate_hash(length=32)` (contoh `set_password`/`magic-link`). Reusable sehingga expiry (bukan one-time — guest boleh balik); re-generate overwrite token lama. Expiry default 7 hari.

**B2. `request_guest_passport_link(booking_number, slot_name, email)`** — `@frappe.whitelist()` di `api/portal_traveller.py`. Dual-auth:
- Admin path: kalau caller ada role Tour Manager/Tour Operator/System Manager → allow terus.
- Customer path: else `_get_customer()` + booking ownership (macam `save_booking_traveller`).
Logic: validate email; resolve booking+slot; generate token; `db.set_value` 3 field; hantar email inline (contoh `send_magic_link_by_email` `portal_auth.py:304-331`) ke guest email dgn link `get_site_url() + "/guest_passport?token=..."`. Return `{status, masked_email, expires_on}`. Re-call = regenerate (link lama invalidated).

**B3. www/guest_passport page** — `www/guest_passport.py` (`allow_guest=1, no_cache=1`) + `www/guest_passport.html`:
- Python: read `token` param; minimal context (no `guard_context` — guest bypass).
- HTML: refactor — extract form 3-section + wizard + confirm bar dari `docs.html` ke partial `templates/includes/traveller_docs_form.html`; kedua-dua `docs.html` & `guest_passport.html` `{% include %}` partial. Guest page: header ringkas (trip name + slot label + "signed in as guest via email link"), tiada portal nav. `pageData` JSON: `{mode:"guest", token:"..."}`.
- JS: kongsi `portal_traveller_page.js` dgn guest-mode branching (lihat B5).

**B4. Factoring** — extract logik persist dari `save_booking_traveller` (`portal_traveller.py:180-327`) ke `_persist_traveller_section(booking, slot, slot_name, section, actor, **fields)`. Termasuk: traveller create/find, contact/health update, PDPA log (guna `actor` bukan `frappe.session.user`), slot link, file upload. `save_booking_traveller` (session) & `save_booking_traveller_guest` (token) kedua-dua panggil core. `actor` = session user (customer) atau guest email.

**B5. `verify_guest_token(token)`** — `@frappe.whitelist(allow_guest=True)`. Lookup Booking Reservation by `passport_link_token`; check `passport_link_expires_on` (throw if expired); check `document_status != Verified` (locked). Return slot context (booking_number, slot_name, slot_label, trip_name, departure_date, SEMUA field traveller untuk pre-fill, has_passport, has_visa_photo) — guest equivalent of `get_booking_data` scoped ke 1 slot.

**B6. `save_booking_traveller_guest(token, section, **fields)`** — `@frappe.whitelist(allow_guest=True)`. Validate token+expiry+lock; resolve booking+slot; panggil `_persist_traveller_section(booking, slot, slot_name, section, actor=passport_link_email, **fields)`. Return same shape as `save_booking_traveller`.

**B7. `confirm_traveller_documents_guest(token)`** — `@frappe.whitelist(allow_guest=True)`. Validate token; panggil logik confirm sedia (factor dari `confirm_traveller_documents` `:856-937` atau inline call dgn ignore_permissions).

**B8. JS guest mode** — `portal_traveller_page.js`: tambah `_GUEST_MODE` (from `_pageData.mode`), `_GUEST_TOKEN`. Branch API calls: `verify_guest_token` (vs `get_booking_data`), `save_booking_traveller_guest` (vs `save_booking_traveller`), `get_guest_file` (vs `get_slot_file`), `confirm_traveller_documents_guest`. Form logic (sections, validation, OCR wizard) tak berubah — reuse penuh.

**B9. Portal trigger UI** — slot list page (`index.html` slot cards, di-render JS): setiap slot tambah action "Send passport link" + email input. Pre-fill email jika slot dah ada `email`. On click → `request_guest_passport_link`. Tunjuk status (link sent, expires_on). Tambahan kecil dalam `portal_traveller_page.js` slot-card render.

**B10. Desk button (admin)** — client script fixture pada Booking Reservation: button "Generate Guest Passport Link" → prompt email → `frappe.call` `request_guest_passport_link`. Tunjuk token/expiry field (B1) read_only pada form. (~30 baris JS dalam `fixtures/client_script.json` atau `public/js/` desk custom.)

## Part C — Nav fix (#4, enabler)

Diperlukan supaya guest page (dan docs page) navigation berfungsi. Diterapkan pada form partial + `portal_traveller_page.js`:

**C1.** `TVL_TAB_ORDER = ['passport', 'contact', 'health']` (sekarang `['info','passport','visa','health']` — `:722`) supaya `tvlNext`/`tvlBack` `indexOf` match panel sebenar.

**C2.** `saveTraveller(section, btn)` — terima `section` & `btn` params; hantar `section` ke API; guna `btn` untuk UI feedback (bukan `get('tvl-save-btn')` yang tak wujud).

**C3.** Button layout ikut spec user (dalam partial):
- Section 1 (passport): Back (`btn-g`) / Save Passport (`btn-p` primary) / Next (`btn-g`)
- Section 2 (contact): Back / Save Contact (`btn-p`) / Next
- Section 3 (health): Back / Save Health (`btn-p`)
Un-comment section-1 Next.

**C4.** Wire `tvl-confirm-btn` (`docs.html:327`) → `confirm_traveller_documents` (customer) / `confirm_traveller_documents_guest` (guest).
