# Pelan: Company-currency transactions + display converter, dan Overbooking gate (0 = unlimited)

Berdasarkan keputusan: (1) harga disimpan dalam company currency, `Trip Package.currency` jadi hint display-default; (2) peraturan 0=unlimited apply pada trip-level `max_participants` DAN per-cabin `max_capacity`; (3) converter tawarkan semua Currency yang ada rate.

## PART 2 — Overbooking gate (max = 0 → unlimited)

### 2A. Trip-level gate (`Trip Group Date.max_participants`)

**`api/booking_engine.py` (`confirm_booking`, selepas line 117)**:
- Estend `get_value` Trip Group Date (line 114) untuk baca `max_participants`, `current_participants`, `status`.
- Jika `max_participants > 0`:
  - `existing_pax = SUM(b.booked_pax) FROM tabBooking b WHERE b.trip_date=%s AND b.status != 'Cancelled'` (atau max(0, ...)).
  - `incoming_pax = sum(int(sel.main_guests)+int(sel.extra_beds)+int(sel.infants) for sel in selections)`.
  - Jika `existing_pax + incoming_pax > max_participants` → throw "This trip date is full. Only {max-existing} seats left." (atau "Sold out" kalau 0).
- Jika `max_participants == 0` → skip (unlimited/overbooking dibenarkan).

**`travel_booking_management/doctype/booking/booking.json`**: tambah field stored `booked_pax` (Int, "Booked Pax", read_only, `non_negative`). Bukan virtual (berbeza dari virtual `total_pax` sedia). Set di `confirm_booking` = incoming_pax. Backfill via patch (lihat 2E).

### 2B. Per-cabin gate (`Trip Price Category.max_capacity`)

**`api/pricing.py` `_validate_selection_capacity` (line 314-369)** — mirror peraturan 0=unlimited pada `max_capacity`:
- `max_capacity = int(info.get("max_capacity") or 0)`.
- Jika `max_capacity == 0`: skip semak `total > max_capacity`; set `max_extra` dan `max_infant` = unlimited (tak throw walaupun besar). Kekal rule structural: main_guests `1..capacity`, extra-bed-only-when-main-full, infant-needs-main-guest. (Jika `capacity == 0` juga, treat main_guests cap unlimited — defensive.)
- Jika `max_capacity > 0`: kekal logik sedia.

**`travel_booking_management/doctype/booking_reservation/booking_reservation.py` `validate_cabin_capacity` (line 86-168)** — mirror sama: bila `max_capacity == 0`, skip `total > max_capacity` dan set budget extra/infant unlimited. (Jaring keselamatan Doctype-level.)

### 2C. Konsistensi paparan (0 = unlimited di semua tempat)

- **`trip_group_date.py` `available_slots` @property (line 140-142)**: pulangkan `None` bila `max_participants == 0` (bukan `0 - current` negatif).
- **`api/trip_manager.py` `get_trip_bundle` (line 173)**: sama — `available_slots = None` bila max==0.
- **`web_data.py`**: dah ada 0-guard (line 212, 217, 425, 429) — tiada ubah. Paparan awam dah betul.
- **Admin JS** (`trip_manager.js:490`, `trip_group_date.js`): papar "Unlimited" bila `available_slots is None` / `max==0`. Minor tweak.

### 2D. Wizard UX (booking.js step 0)

- **`www/booking.py` (line 56-84)**: pass `max_participants`, `current_participants`, `seats_left` (0=unlimited → `None`) ke wizard. Kekal filter `status='Active'`.
- **`public/js/booking.js` step 0 (line 279-333)**: tunjuk badge "N seats left" atau "Available" (unlimited); disable tarikh penuh (`seats_left == 0` bila `max > 0`). Sync dengan gate server.

### 2E. Patch backfill

- **Patch** (`travel_booking/patches/v1_backfill_booked_pax.py`): untuk setiap Booking sedia ada, set `booked_pax` = COUNT `tabBooking Reservation` (non-cancelled) bagi booking itu (best-effort — paid pax). Booking Pending lama (tiada reservation) akan `booked_pax=0`; caveat: gate undercount untuk historical pending, tapi gate forward-looking jadi betul untuk booking baru.

## Pengasingan tugas (cadangan urutan)

Kedua-dua part tak bergantung — boleh buat serentak atau berasingan. Cadangan:
1. **Part 2 (overbooking)** dahulu — lebih kecil, terkawal, nilai segera (halang overbooking).
2. **Part 1 (currency)** — lebih besar, sentuh banyak permukaan; pecah kepada: 1A+1B+1E (server+schema+migrasi) → 1C (converter) → 1D (settings cleanup).

Selepas siap, simpan memori tentang keputusan senibina ini (company-currency + converter + overbooking 0-rule) untuk sesi akan datang.
