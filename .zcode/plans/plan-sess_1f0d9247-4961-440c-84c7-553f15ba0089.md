## Langkah Pelaksanaan

### 1. Kiraan pengesahan pra-padam (read-only)
Kira rekod Error Log setiap site melalui mysql terus (kredensial dari `sites/<site>/site_config.json`):
- DB: `_67f130efb9725661`(_rare), `_5236c6aef46ee5b0`(_rpwp), `_910e77e07cb65dce`(_edu), `_a368aabef9d2bbd7`(_health), `_5df7d3c83a22e92a`(_snap), `_8295415120d09a30`(_warga)
- `SELECT COUNT(*) FROM \`tabError Log\`;` — rekod angka tepat untuk laporan akhir

### 2. Padam rekod Error Log DB (semua 6 site)
Per site: `bench --site <site> execute frappe.db.delete --args '["Error Log"]'`
- Fallback jika bench bermasalah: `DELETE FROM \`tabError Log\`` terus melalui mysql
- Nota: rekod `_rare` boleh dipulihkan dari backup dump 18 Nov 06:00; **`_rpwp`/`_snap`/`_warga` TIADA backup — pemadahan kekal (separuh kritikal, lihat #1)**

### 3. Padam fail error log pada disk
- `rm -f /home/frappe/frappe-bench/logs/*.error.log*` (semua rotasi `.1`–`.7` dan `.gz`: web, worker, schedule, redis-cache, redis-queue, node-socketio)
- Fail root-owned (`redis-socketio.error.log`): cuba `sudo -n` dahulu; jika tiada sudo, truncate `> file` jika boleh tulis, jika tidak laporkan sebagai tidak dapat dipadam
- Juga fail error log dalam `sites/*/logs/` jika wujud (`.error.log*` sahaja — fail frappe.log umum TIDAK disentuh)

### 4. Pengesahan
- Ulang `SELECT COUNT(*)` → 0 bagi setiap site
- `ls /home/frappe/frappe-bench/logs/*.error.log*` → tiada lagi (kecuali yang root-owned gagal dipadam, dilaporkan)
- Output akhir: jadual sebelum/selepas (kiraan DB + fail dipadam)

### Yang TIDAK dilakukan (cadangan susulan sahaja)
- Tidak membaiki bug backup Error 2013, bug pembayaran PR.company/permission, atau pembersihan worker.log 419MB — di luar skop permintaan ini
