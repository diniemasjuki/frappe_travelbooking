# Pelan: Website Booking System berdasarkan doctype TRIP (Rarecation)

## Analisa kelayakan (Feasibility) — ringkasan

**Sangat boleh dibina.** Hampir semua backend booking dah wujud dan dipakai semula as-is; bahagian *greenfield* ialah pengalaman katalog/browsing awam + template detail trip + (skema baru) itinerary.

Yang **sedia ada & dipakai semula**:
- Backend booking penuh: `booking_engine.confirm_booking`, `pricing.get_booking_details`/`get_payment_settings`, `stripe_checkout`, voucher/affiliate, engine status + hooks (`travel_booking/api/`).
- Portal pelanggan pasca-booking (`www/traveller_portal/`, `api/portal_*`).
- Query "trip ready" di `www/booking.py` (sumber data katalog: trips + group dates + packages + `seats_left` + flag cruise).
- Web-doctype Trip auto-route ke `/trip/<slug>` + `index_web_pages_for_search:1` (carian Frappe percuma).
- Jinja globals `asset_v`/`get_company_currency`/`get_company_symbol` (`hooks.py jinja.methods`), helper `portal_common.js` (`_esc`, `fmt`, `RC` converter), konvensyen `?v=` cache-busting.

Yang **kena bina baru (greenfield)**:
- Page katalog awam `/trips` (listing + filter + search + grid card) — tiada sekarang (hanya dropdown di step-1 wizard).
- Template detail trip sebenar mengganti stub `templates/trip.html` (sekarang cuma `<h1>{{ title }}</h1>`).
- Child table **"Trip Itinerary"** baharu + medan pada Trip untuk paparan day-by-day (tiada skema sedia ada — lihat Fasa 1).
- Site chrome global (nav/footer) — tiada `website_context`/base-template hook sekarang.
- Rombak step-1 wizard jadi card-based (integrasi lebih dalam, ikut pilihan anda).

Skop dikecilkan mengikut keputusan anda: **filter features guna field sedia ada** (`trip_categories` + `is_a_cruise_trip`), **booking integrate lebih dalam** (step-1 jadi card-based).

---

## Reka bentuk senibina (keputusan)

1. **Routing**: Katalog di `/trips` (page `www/`); detail trip kekal di `/trip/<slug>` (auto-route web-doctype) tetapi guna **template custom** `templates/trip.html`. Perhatian: `trip.py before_save` jana `route = "trip/" + slug` tanpa dedup — cadang tambah suffix `-2` kalau nama trip berulang (elak perlanggaran URL/SEO).
2. **Base template**: Bina `templates/base_travel.html` (extend `templates/web.html`, block nav/footer) untuk page awam. Tambah hook `website_context` di `hooks.py` untuk inject logo/company-currency/csrf setiap page awam. Portal kekal standalone (login-scoped, chrome berasingan) — tak diusik.
3. **Stack frontend**: Vanilla JS + `www/*.py`+`.html` + Jinja, **sepadan dengan portal sedia ada** (bukan framework baharu). Guna semula `portal_common.js` helper + Tabler Icons + Google Fonts (Archivo/DM Serif) sedia ada.
4. **Sumber data katalog**: Adaptasi query "ready trip" dari `www/booking.py` ke `www/trips.py` + tambah filter (date/destination/item-group/cruise). Jangan duplikasi logic — pecah query terbabit ke `travel_booking/utils/trip_catalog.py` supaya `www/booking.py` & `www/trips.py` pakai sama.

## Fasa 1 — Skema data: Child table "Trip Itinerary" (jawapan kepada soalan anda)

Untuk paparkan senarai itinerary **day-by-day** setiap trip, perlu bina child table baru sebab tiada struktur sedia ada (field `flight_itinerary` sedia ada hanyalah TextEditor blob segmen penerbangan, bukan jadual hari berstruktur).

**Bina doctype child table `Trip Itinerary`** (`travel_booking/travel_booking_management/doctype/trip_itinerary/trip_itinerary.json`, `istable:1`). Medan:

| fieldname | fieldtype | label | nota |
|---|---|---|---|
| `day` | Int | Day | reqd, in_list_view, non_negative, in_list_view (1, 2, 3…) |
| `day_title` | Data | Day Title | reqd, in_list_view (cth: "Embarkation — Jeddah", "Day at Sea") |
| `description` | Text Editor | Description | aktiviti/nota hari tu |
| `destination_point` | Link → Trip Destination Point | Destination/Port | pilihan; recycle master sedia ada (ada `destination_country`, `destination_image`, `destination_description`) |
| `day_image` | Attach Image | Image | gambar hari tu (boleh kosong, fallback trip_image) |
| `meals` | Select | Meals | `Breakfast/Lunch/Dinner` (atau 3 medan Check jika nak lebih terperinci) |

**Tambah medan child table pada Trip** (`trip.json`): `itinerary` (fieldtype Table, options `Trip Itinerary`) dalam section baharu "Itinerary". Tambah sekali ke `TRIP_FIELDS` di `api/trip_manager.py` supaya entry admin (Desk `Trip Manager` page) sokong.

**Validasi**: `validate()` Trip boleh lepas — jumlah `day` maksimum patut match `Trip Cruise Schedule.total_days` (cruise) atau `Trip Group Date.total_days` (non-cruise) sebagai amaran lembut, bukan hard block (elak halangan kalau itinerary belum disusun).

**Paparan**: Di detail page (Fasa 3), render `itinerary` sebagai **timeline menegak** — setiap row: "Day N | title | destination badge + bendera | gambar | description | meals". Kalau user dah pilih tarikh keberangkatan di page tu, kira tarikh sebenar: `actual_date = base_date + (day - 1)` (cruise: `sailing_start`; non-cruise: `departure_date`), papar "Day 1 — 15 Mac 2026".

## Fasa 2 — Page katalog awam `/trips`

Fail: `travel_booking/www/trips.py` + `trips.html`, JS `public/js/trips.js`, CSS `public/css/trips.css`.

**Query (reuse + extend)**: `www/trips.py get_context` panggil `trip_catalog.get_ready_trips(filters)` dari `travel_booking/utils/trip_catalog.py` (dipecah dari query `www/booking.py`). Tambah field untuk card: `trip_image`, `trip_categories`, `destination_list` (join ke `Trip Destination Point` untuk nama destinasi + negara), dan `starting_from_price` (MIN harga dewasa dari `Trip Package Price.price_adult` merentasi package Active trip tu) + `next_departure` (group date Active terdekat).

**Filter & search** (semua dari field sedia ada, ikut pilihan "guna field sedia ada"):
- **By date**: range picker → `Trip Group Date.departure_date` (non-cruise) / `sailing_start` (cruise). Hanya trip dengan group date dalam range dipaparkan.
- **By destination**: dropdown dari `Trip Destination Point` → join `destination_list` (child `Trip Destination Point Select`). Untuk cruise, sertakan juga `Trip Cruise Schedule.port_start/port_end`.
- **By item group**: dropdown `Item Group` (Trip.trip_categories).
- **By features (cruise/normal)**: toggle/kategori dari `Trip.is_a_cruise_trip`.
- **Text search**: keyword atas `trip_name`/`title` (memanfaatkan `index_web_pages_for_search`).

**Card grid** (gaya cruise.rarecation.com): setiap card — cover image (`trip_image`), badge cruise/non-cruise + item group, title, destinasi, duration (`total_days`/`total_nights`), harga "from RM X" (`starting_from_price` dalam company currency + converter display), tarikh keberangkatan seterusnya, badge availability (`seats_left` → "Available"/"Selling fast"/"Sold out"), butang "Book Now" → `/booking?trip_master=<trip.name>` (deep-link, langsung ke step-2 bila trip dipilih).

**Tambahan UX**: sort (tarikh/price/duration), pagination/infinite-scroll, empty-state.

## Fasa 3 — Template detail trip `templates/trip.html` (ganti stub)

Ganti stub `travel_booking/travel_booking_management/doctype/trip/templates/trip.html` (extend `templates/base_travel.html`) — Frappe auto-gunakan template ini untuk web-view Trip di `/trip/<slug>`. Seksyen:

1. **Hero gallery**: `trip_image` cover + `attachment_gallery_okqc` (Attachment Gallery → multi-image carousel/lightbox).
2. **Header**: `trip_name`, badge cruise/non-cruise + item group, destinasi (dari `destination_list`), organizer (`trip_organizer` + logo).
3. **Overview/description**: `description` (rich text).
4. **Itinerary timeline**: child table `itinerary` (Fasa 1) — papar day-by-day. Jika user pilih tarikh departure di widget kat sini, kira & papar tarikh sebenar setiap hari.
5. **Departure dates + packages**: widget pilih `Trip Group Date` (Active, future) → papar package berkaitan + harga pax (dewasa/kanak) via `pricing.get_booking_details(trip_group_date, trip_package)` (API sedia ada, `allow_guest=True`). Papar `seats_left`. 
6. **Pricing**: `starting_from_price` + converter display-currency (reuse `RC` dari `portal_common.js`).
7. **CTA "Book Now"**: bawa `trip_master` + `trip_group_date` terpilih ke `/booking` (deep-link, langsung ke step 2).
8. **Related trips**: trip lain dengan `trip_categories`/destinasi sama.

**SEO**: tajuk/meta dari `trip_name`/`description`; tambah JSON-LD `TouristTrip` (schema.org) utk rich snippet — nama, deskripsi, lokasi, tarikh, harga.

## Susunan pelaksanaan (cadang)
1. **Fasa 1** (itinerary skema) — 2 hari: bina child doctype + medan Trip + entry admin.
2. **Fasa 0/senibina** — 1 hari: `base_travel.html` + `website_context` hook + `utils/trip_catalog.py` (pecah query booking.py).
3. **Fasa 2** (katalog `/trips`) — 3 hari: page + filter + card grid.
4. **Fasa 3** (detail `templates/trip.html`) — 3 hari: gallery + itinerary timeline + departure widget + CTA.
5. **Fasa 4** (rombak step-1 card) — 2 hari.
6. **Fasa 5** (penambahbaikan) — ikut keutamaan.

## Risiko/nota
- `trip.py before_save` jana route tanpa dedup → perlanggaran URL kalau nama trip berulang; cadang baiki awal (Fasa 0).
- `www/booking.py` query & `pricing.get_booking_details` adalah sumber kebenaran untuk "ready trip" & harga — jangan re-implement; pecah & reuse sahaja.
- Template detail (`templates/trip.html`) extend `templates/web.html` → akan dapat chrome Frappe; pastikan `base_travel.html` konsisten dengan portal (logo/font) supaya tak kelihatan dua gaya.
- Tidak sentuh skema harga/kapasiti (company-currency + `booked_pax` overbooking model) — pegang senibina sedia ada.
