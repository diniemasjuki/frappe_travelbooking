## Analisis: macam mana ProformaInvoice proses sekarang

Halaman `/traveller_portal/booking_billing?ref=...`:

1. `booking_billing.py` → `get_context` set `booking_ref`, `_guard` pastikan customer login.
2. `portal_billing.js` `loadBookingPayments()` → `API_PM('get_all_so_payments')` (di `api/portal_payment.py`).
3. `renderSoCard()` → `renderDocumentsSection(so, symbol, isPaid, isCancelled)`.
4. Bila SO **belum lunas** (`!isPaid`): render baris "Proforma Invoice" + butang **"↓ Print Proforma"** → `downloadDocument('Sales Order', so.name)`.
5. `downloadDocument()` POST ke `get_document_pdf` dengan `{doctype:'Sales Order', docname: so.name}`.
6. Branch "Sales Order" dalam `get_document_pdf` → verify pemilikan → **render SO semula** guna Print Format `"Rarecation Proforma Invoice"` (`PRINT_FORMAT_PROFORMA`) → pulangkan PDF.

**Masalah:** "Proforma Invoice" hari ini **bukan dokumen sebenar** — ia cuma Sales Order dicetak semula guna print format custom. Tiada rekod `Proforma Invoice` terlibat.

ERPNext sebenarnya ada doctype **`Proforma Invoice`** sebenar (module Selling, `enable_proforma_invoice=1` sudah dihidupkan). Ia link ke Sales Order via field `sales_order`, boleh di-submit, dan on-submit jana PDF sebenar disimpan dalam field `proforma_pdf`. 2 rekod issued dah wujud (PRO-2026-00001/00002 utk SO SAL-ORD-2026-00008/00009) — tapi portal abaikan, masih cetak SO semula.

## Pelan pelaksanaan

**Skop:** bahagian (1) sahaja — ambil proforma terus dari doctype. Butang Telegram **dibatalkan** mengikut keputusan awak; bila tiada proforma, tunjuk nota neutral.

### Fail 1 — `travel_booking/api/portal_payment.py`

**A. `get_all_so_payments()` — dedah rekod Proforma Invoice sebenar:**
Dalam loop setiap SO (bila `so.docstatus == 1`), fetch proforma issued:
```sql
SELECT name, proforma_date, grand_total, proforma_pdf, status, currency
FROM `tabProforma Invoice`
WHERE sales_order=%s AND docstatus=1
ORDER BY creation DESC
```
Tambah `so["proformas"] = [{name, proforma_date, grand_total, proforma_pdf, status, currency}, ...]` pada setiap order dict (list kosong kalau tiada/cancelled SO).

**B. `get_document_pdf()` — tambah branch `"Proforma Invoice"` (download PDF sebenar):**
- Load proforma → ambil `sales_order`.
- Verify SO itu `customer == _get_customer()` (pemilikan, sama corak branch lain).
- Cari File ikut `proforma_pdf` (`attached_to_doctype='Proforma Invoice'`, `attached_to_name=<proforma>`), baca content guna `File.get_content()`.
- Pulangkan sebagai PDF download (sama response shape: `filename`, `filecontent`, `type:'download'`, `content_type:'application/pdf'`).
- Kalau `proforma_pdf` kosong/tiada File → return `{status:'error', message:'Proforma PDF not available.'}` (http 404).
- Branch "Sales Order" lama (proforma fake via `PRINT_FORMAT_PROFORMA`) **kekal** tak disentuh — UI tak panggil lagi, rendah risiko.

### Fail 2 — `travel_booking/public/js/portal_billing.js`

**C. Refactor `renderDocumentsSection()` — blok `!isPaid`:**
- Kalau `so.proformas.length` → satu baris per proforma issued: ikon dokumen + `PRO-...` (monospace) + tarikh + jumlah + butang **"↓ Proforma"** → `downloadDocument('Proforma Invoice', p.name)`. (Mirror struktur baris Sales Invoice sedia ada.)
- Kalau kosong → nota neutral: *"Your proforma invoice will appear here once it has been issued."* (English, selari dengan teks sedia ada "Official invoice will appear here once it has been generated.")
- Buang butang "↓ Print Proforma" lama (yang panggil `downloadDocument('Sales Order', so.name)`).
- Bahagian "lunas + SI wujud" / "lunas tiada SI" → kekal macam asal (laluan Sales Invoice).

`downloadDocument()` sedia ada tak perlu ubah — ia dah hantar `doctype`/`docname` generik ke `get_document_pdf`, jadi "Proforma Invoice" branch baru terus jalan.

### Yang TIDAK berubah
- Tiada perubahan doctype, tiada migrasi, tiada Telegram, tiada field Travel Settings baharu.
- `PRINT_FORMAT_PROFORMA` / Print Format "Rarecation Proforma Invoice" (Sales Order) jadi orphan di portal — kekal (tak dipadam), tak ganggu apa-apa.
- PDF proforma sebenar guna Print Format standard ERPNext "Proforma Invoice" (ikut `default_proforma_print_format` di Selling Settings). Kalau mahu branding Rarecation atas PDF proforma, itu kerja print-format berasingan (admin set format custom) — di luar skop ni.
