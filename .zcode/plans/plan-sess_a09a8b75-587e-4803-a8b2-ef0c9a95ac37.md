## Authorization Model + Login Card UI

### A. New Authorization Model: Traveller Role as Gatekeeper

**Core change:** Portal access is gated by the `Traveller` role (not by Customer record). On signup, the role is only assigned if a booking exists for the user's email. No booking = no role = "under review" state.

---

#### 1. `travel_booking/api/portal_auth.py` — signup rewrite + check_session change + new helper

**Add `_email_has_booking(email)` helper** (new function):
```python
def _email_has_booking(email):
    """True kalau ada rekod Booking dengan cust_email = email ni.
    Guna cust_email snapshot field (ditulis semasa booking dicipta)."""
    if not email:
        return False
    return bool(frappe.db.exists("Booking", {"cust_email": email}))
```

**Rewrite `signup()`** (lines 446-537):
- Remove ALL Customer+Contact creation (Customer is created during the booking flow's `_create_customer()`, not at signup)
- Create User **WITHOUT** any role (remove `"roles": [{"role": "Traveller"}]`)
- Call `_email_has_booking(email)`:
  - If booking exists → assign Traveller role via `user.append("roles", {"role": "Traveller"})` + save → return `{"status": "ok", "role_assigned": True, "email": email, "message": "..."}`
  - If no booking → leave User with no role → return `{"status": "ok", "role_assigned": False, "email": email, "message": "Your account is under review..."}`

**Modify `check_session()`** (lines 87-184):
- Replace the `if not customer_name:` block (lines 131-157) with a Traveller role check:
  - `if "Traveller" not in frappe.get_roles(user_email):` → return `{"status": "under_review", "logged_in": True, ...}` (was `"no_customer_link"`)
  - If has Traveller role but no Customer → return `"ok"` with empty bookings (existing behavior, keep as-is)
  - If has Traveller role + Customer → return `"ok"` with bookings (existing, keep as-is)

#### 2. `travel_booking/api/booking_engine.py` — `_ensure_portal_user()` (lines 784-817)

When User already exists (e.g., signed up via portal but had no booking), ensure the Traveller role is assigned:
```python
if frappe.db.exists("User", email):
    user = frappe.get_doc("User", email)
    if "Traveller" not in [r.role for r in user.roles]:
        user.append("roles", {"role": "Traveller"})
        user.flags.ignore_permissions = True
        user.save()
        frappe.db.commit()
    return False
# ... existing User creation with Traveller role (unchanged)
```
This ensures a user who signed up first (under review) and later makes a booking gets the Traveller role automatically.

Remove the `if require_customer and not customer:` redirect block — Traveller role is the sole gatekeeper. Keep `require_customer` param for API compat but it no longer redirects. Keep setting `customer_name`/`customer_label` in context if Customer exists.
