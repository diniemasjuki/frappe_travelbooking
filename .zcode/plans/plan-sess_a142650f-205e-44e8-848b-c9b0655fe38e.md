# Plan: Add Missing Features/Settings to `get_website_settings` Endpoint

## Current State Analysis

**Current Implementation** (`trip_command_center.py:158-210`) returns only **16 fields**:
- Basic branding (logo, footer_tagline, support_email, copyright_text, social media)
- Cruise/Tour: hero_title, hero_subtitle, hero_stats, benefits, testimonials

**Available in Travel Website Doctype** but **MISSING from API**: **40+ fields**

### 2. **Complete Hero Section** (Priority: High)

### 3. **Featured Section** (Priority: Medium)

### 4. **Why Choose Us Section** (Priority: Medium)
- `whyus_tag`, `whyus_title`, `whyus_subtitle`

### 5. **Destinations Section** (Priority: Medium)
- `dest_tag`, `dest_title`, `dest_subtitle`

### 6. **Testimonials Headers** (Priority: Low)
- `testi_tag`, `testi_title`, `testi_subtitle`

### 7. **Call-to-Action Block** (Priority: Medium)

- `cta_primary_label`, `cta_primary_url`
- `cta_secondary_label`, `cta_secondary_url`

### 8. **Enhanced Data Quality** (Priority: High)
- Filter child table rows by `is_active` flag
- Sort results by `sort_order` and `idx` fields

## Implementation Approach

### Option A: Extend Current Flat Structure (Recommended)
Keep the current flat naming convention (`cruise_hero_title`) that the frontend already uses, but add all missing fields. This minimizes frontend changes.

### Option B: Switch to Nested Structure (Like website_config.py)
Return hierarchical dict (`cruise.hero.title`) matching the template utility. Requires frontend refactoring but cleaner long-term.

**Recommendation**: Option A for immediate enhancement, with Option B as future refactoring.
