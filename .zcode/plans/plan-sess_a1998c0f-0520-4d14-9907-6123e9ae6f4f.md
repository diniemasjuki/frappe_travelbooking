## Fix: Monkey-patch Frappe `create_contact` to Handle Error 1020

### Problem
Frappe's `frappe.core.doctype.user.user.create_contact()` (Path B — updating existing Contact) hits error 1020 when it tries to `.save()` a Contact that our `_create_customer()` just created/modified in the same transaction. The `FOR UPDATE` lock detects the row changed.

### Fix: Add `app_init` hook in hooks.py

Add a monkey-patch that wraps `create_contact` to catch `QueryDeadlockError` / `InternalError` (error 1020) on the `.save()` path and convert it to `RetryBackgroundJobError` (which Frappe's BG job runner already knows how to retry).

**File:** `travel_booking/hooks.py`

```python
# In hooks.py, add:
app_init = "travel_booking.patches.patch_create_contact.apply"
```

**New file:** `travel_booking/patches/patch_create_contact.py`

```python
import frappe
from frappe.exceptions import QueryDeadlockError

def apply():
    import frappe.core.doctype.user.user as mod
    _orig = mod.create_contact
    
    def _patched(user, *args, **kwargs):
        try:
            return _orig(user, *args, **kwargs)
        except (QueryDeadlockError, frappe.db.InternalError) as e:
            # Error 1020 / deadlock on Contact save — retry via BG job runner
            raise frappe.RetryBackgroundJobError from e
    
    mod.create_contact = _patched
```

This is safe: `RetryBackgroundJobError` is exactly what Path B already raises for `TimestampMismatchError`. No framework files touched.
