# Plan: Page Pengurusan Trip Unified (`/manage/trips`)

## Pendekatan

Satu page staff-only untuk Tour Manager & Tour Operator mengurus **Trip + Trip Group Date + Trip Package** dalam satu tempat, ikut pattern sedia ada app (**www page + whitelisted API + vanilla JS** — sama macam portal traveller). Tiada perubahan schema; Desk form & calendar kekal.

**Prinsip penting:** semua tulisan dibuat melalui `frappe.get_doc + insert()/save()` (bukan `db.set_value`), supaya semua logic `validate()` sedia ada terus berfungsi — auto-generate `trip_group_name/code`, `package_code/title`, `price_variant_code`, kiraan `total_days/nights`, validasi tarikh & logic cruise.

Keputusan scope (tiada jawapan diterima, guna recommendation): www page · sokongan cruise penuh · create + edit.

## Fail baru (5)

### 1. `travel_booking/www/manage/trips.py` — context & guard
- `no_cache = 1`
- Guard server-side (ikut `_guard.py` pattern): Guest / bukan role **Tour Manager|Tour Operator** → redirect ke `/login`
- Context: `csrf_token`, nama user, `can_delete` (Tour Manager sahaja), `is_manager`

### 2. `travel_booking/www/manage/trips.html` — UI
Standalone HTML (tak extend `web.html`), design tokens `--rc-*` + Archivo + Tabler icons (sama macam `www/trips.html`). Struktur:
- **Topbar**: logo, tajuk "Trip Manager", nama user, logout
- **Sidebar kiri**: senarai trip (search, filter status), butang **"+ Trip Baru"**; row = thumbnail, `trip_name`, organizer, badge `published`/`status`, kiraan tarikh & pakej
- **Panel utama, 3 tab**:
  1. **Maklumat Trip** — `trip_name`, organizer *(disabled selepas create — set_only_once)*, cover image (upload via `frappe.handler.upload_file`), destination multi-select chips, SEO route, toggle `published`, `status`, description
  2. **Tarikh Departure** (Trip Group Date) — table: nama group, departure–return (+ "8D7N"), capacity/occupancy/vacancy, status badge, butang edit; modal tambah/edit: `departure_date`, `return_date`, `max_participants`, `status`, description; **untuk trip cruise**: picker `cruise_schedule` (filtered ke trip ini), toggle `is_cruise_only` *(disabled selepas create)*, info sailing/ship/port dipaparkan read-only (fetched)
  3. **Pakej** (Trip Package) — kad: `package_title`, type, airport, currency, chips tarikh terpilih; modal tambah/edit: `package_type` (opsyen diikut logik `trip_package.js`: cruise → Fly Cruise/Cruise Only; biasa → Fly Package/Ground Only/Customed; **locked selepas create**), `airport_form` (wajib Fly Package), `currency` (default MYR, cadangan dari airport), `select_group_by_date` (chips dari Group Dates trip ini, difilter `is_cruise_only`), **grid pricing** (kategori × 6 kolum harga: adult_single, adult, upperberth, children, toddler, infant); **untuk cruise**: butang **Import dari Cruise Rate** (salin `cabin_rates` dari cruise schedule terpilih — replikasi logik `trip_package.js`)
- Occupancy (`current_participants`/`available_slots`) read-only sahaja
- Delete tarikh/pakej: butang hanya muncul jika `can_delete` (ikut permission doctype — Tour Operator tiada delete)

### 3. `travel_booking/api/trip_manager.py` — API layer
Semua `@frappe.whitelist()`, **type-annotated** (`require_type_annotated_api_methods = True`), helper `_require_manager()` check role di awal setiap method:
- `get_managed_trips(status: str = "", q: str = "") -> list[dict]` — senarai trip + organizer + published/status + kiraan dates & packages
- `get_trip_bundle(trip: str) -> dict` — Trip fields + group dates + packages (dengan `select_group_by_date` & `package_pricing`) + lookups dalam satu call (Trip Organizer, Trip Destination Point, Flight Airport+currency, Currency, Trip Price Category, Trip Cruise Schedule trip ini)
- `save_trip(payload: dict) -> dict` — create/update Trip (route auto-slug oleh `_default_route` jika kosong)
- `save_group_date(payload: dict) -> dict` — create/update; server generate nama/kod/hari; jika `naming_series` tak ter-fetch semasa insert, set eksplisit dari `Trip Organizer.org_series`
- `save_package(payload: dict) -> dict` — termasuk child tables; strategi **full-replace dengan kekalkan row name sedia ada** untuk `pricing_for_class` yang sama (elak `price_variant_code` berubah)
- `delete_doc(doctype: str, name: str) -> dict` — hadkan kepada 3 doctype ini + `frappe.has_permission(doctype, "delete")`

### 4. `travel_booking/public/js/trip_manager.js` — client logic
Vanilla JS, ikut pattern portal: baca CSRF dari `#pageData`, `fetch("/api/method/travel_booking.api.trip_manager.*")` (GET baca / POST JSON tulis — `use_json_request_body = True`), render list + tab + modal, toast selepas save, reload bundle selepas setiap operasi. Kategori pricing difilter oleh `is_a_cruise` trip.

### 5. `travel_booking/public/css/trip_manager.css` — style
Reuse tokens `--rc-*` dari design Rarecation sedia ada.

Semua asset canonical di `travel_booking/public/` (**bukan** folder `public/` lama di root app), dimuat dengan `?v={{ asset_v(...) }}`.
