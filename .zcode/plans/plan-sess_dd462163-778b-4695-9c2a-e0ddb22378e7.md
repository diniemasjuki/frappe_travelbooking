## Pelan: Pilihan Room Privacy (Private / Open Sharing) — booknow + portal tambah traveller

### Latar (apa yang sudah wujud — tiada perubahan harga diperlukan)
- Cabin cruise 1 pax **sudah dikenakan `price_adult_single`** (`so_helpers.py:224-228`). Kedua-dua pilihan privacy bayar harga sama masa checkout — pilihan ini rekod **janji operasi** (padankan roommate → refund lebihan), bukan perbezaan harga.
- Field `room_privacy` ("Private\nOpen Sharing") **sudah wujud** dalam Booking Reservation (`booking_reservation.json:644`) tapi tidak pernah diisi — kita hanya perlu hubungkan.
- **Keputusan awak:** cruise sahaja · default **Private** · refund **manual oleh ops** · senario kedua = flow portal tambah traveller + SO baharu.

### Fasa 1 — Pilihan privacy dalam wizard booknow

**1. UI — `public/js/booknow.js` (`renderRooms()`, ~js:1780-1837)**
- Bina blok `div.bnw-privacy` dan append selepas `cabinInfo`, sebelum `counters` (betul-betul antara `bnw-cabin-info` & `bnw-steppers`).
- Papar hanya bila `state.is_cruise_trip && room.main_guests === 1`.
- Gaya radio card semula: `.bnw-radio-group` / `.bnw-radio-option` / `.bnw-radio-selected` (pattern payment method, booknow.html:363-393) — 2 pilihan:
  - **Private** — "Keep the cabin to myself."
  - **Open Sharing** — "Open to share with a matched roommate."
- Default **Private** (checked; state kosong = Private).
- Bila `main_guests` berubah 1→2: sembunyikan radio & kosongkan `room.room_privacy`. 2→1: papar semula, default Private.
- **Nota pemaklumat** (`.bnw-notice.bnw-notice-info`, pattern booknow.html:231) papar bila radio dipapar, isi:
  - "We will try to match you with a roommate of the same gender. If a match is found, the single-occupancy difference will be **refunded** to you."
  - "Found your own travel companion? Add them to this cabin later from the Traveller Portal — your excess payment will be **credited** towards their fare."
- State `room.room_privacy` ("Private" | "Open Sharing") menunggang objek room sedia ada → auto persist ke sessionStorage (`saveState`/`restoreWizard`).

**2. Summary** — `buildStep1Summary()` (~js:2150): papar baris "Room Privacy: Open Sharing" untuk cabin 1 pax cruise.

**3. Payload** — `activeSelections` map (booknow.js:4268-4277): tambah `room_privacy` (hantar bila cruise & mg===1, else kosong).

**4. Backend sanitize + simpan**
- `booking_engine.confirm_booking()`: whitelist nilai (`Private`/`Open Sharing`), terima hanya bila `is_cruise && main_guests===1`, else `""`.
- `so_helpers._build_so_items()` / `_so_line()`: terima `room_privacy` per selection → set `custom_room_privacy` pada SO line "Main Guest (Single)".
- **Patch baharu** `patches/v3_so_item_room_privacy.py` (daftar dalam `patches.txt` `[post_model_sync]`): cipta Custom Field `custom_room_privacy` (Select: `Private\nOpen Sharing`) pada **Sales Order Item** via `create_custom_fields` — idempotent. (Fixture `custom_field.json` kosong; patch ialah cara repo-managed.)
- `_cabin_layout_from_so()`: baca `custom_room_privacy` dari SO Item → bawa ke layout dict per cabin.
- `_activate_booking()`: set `room_privacy` pada Booking Reservation yang dicipta.
- Ops visibility: pastikan field nampak dalam Booking Reservation form/list; tambah paparan ringkas dalam Booking Hub cabin view (booking_hub.py) supaya ops nampa siapa minta dipadankan.

### Fasa 2 — Portal: Tambah Traveller ke cabin (senario "sambung bayar dari lebihan")

**1. Kelayakan (semak server-side):** booking aksesibel oleh user portal · status Confirmed/Completed · cruise · ada cabin dengan 1 main guest · kapasiti cabin ≥ 2 · ada tempat lagi dalam trip (seats left).

**2. UI:** halaman detail booking portal (`www/traveller/` + `traveller_detail.js`) — butang "Add Traveller to this Cabin" pada cabin layak → borang traveller baharu (padankan field sedia ada dalam portal_traveller.py) → endpoint baharu.

**3. Endpoint server** (dalam `api/portal_booking.py` atau modul baharu, model pada `checkout_addons`):
- `single_rate` dari SO asal (line "Main Guest (Single)", snapshot), `price_adult` semasa untuk kategori sama.
- `excess = max(single_rate − price_adult, 0)`.
- Cipta **SO baharu** (Administrator): `custom_booking` = booking asal, line "Additional Traveller — Twin Share (Cabin N)" qty 1, rate = `price_adult`, **discount per-row = excess** → net bayaran = `price_adult − excess` (matematik tepat: jumlah terkutop jadi 2×price_adult, seperti twin share sebenar).
- Cipta rekod traveller dalam status pending, aktif selepas bayar.

**4. Bayaran:** guna flow sedia ada `/traveller/billing` + `portal_payment`/Stripe terhadap SO baharu (SO ditemui melalui link `custom_booking`, sama macam addon SO).

**5. Selepas bayar:** extend hook `on_payment_entry_submit` (booking_engine.py) — bila SO tambahan dibayar penuh, cipta Booking Reservation slot (booking asal, `cabin_no` target, pax_type "Main Guest", room_privacy "Open Sharing"). Fallback manual oleh ops jika hook gagal.
