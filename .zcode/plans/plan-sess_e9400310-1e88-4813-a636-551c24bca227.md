# Reka Bentuk B2B / Agen / Reseller — travel_booking

## Konsep ringkas

Satu entiti baru **Travel B2B Partner** menjadi "agen berbilang staf" yang dibilkan. Prinsip utama:

- **`Booking.customer` = Customer B2B partner** (entiti bil) — SO, Payment Entry, Stripe, dan Sales Invoice auto semuanya ke partner. Ini berlaku secara automatik sebab semua dokumen kewangan mengikut `Booking.customer` yang sedia ada.
- **Field baru `Booking.end_customer`** (Link Customer) = pelanggan end-customer yang datanya diisi partner dalam wizard. Dia dapat akaun portal (mekanisma `_ensure_portal_user` sedia ada) tapi **semua endpoint portal memulangkan data TANPA harga/billing** untuknya.
- `booking_channel = "B2B"` (pilihan sedia ada dalam `booking.json:403`) mula digunakan; `booked_by` = staf partner yang tempah.
- **Harga net = diskaun % per partner** (default + override per pakej), dilaksana sebagai baris SO negatif "B2B Discount" — konsisten dengan corak voucher/referral sedia ada. `Booking.pre_discount_total` kekal menyimpan harga runcit → margin = `pre_discount_total − grand_total`.
- Staf/affiliate on-behalf sedia ada **tidak berubah** (masih dibilkan kepada end customer). Hanya saluran B2B yang menukar pihak dibilkan.

## 1. Data model

### DocType baru: `Travel B2B Partner` (module Travel Booking Management)
- `partner_name` (Data, wajib), `status` (Select: Active/Disabled)
- `customer` (Link Customer, wajib, unique) — entiti bil ERPNext; disyorkan set `customer_group` = "B2B" (patch cipta Customer Group)
- `contact_email` (Data) — penerima emel billing partner
- `default_discount_percent` (Percent, wajib ≥ 0)
- `package_discounts` (child `Travel B2B Package Discount`: `trip_package` Link, `discount_percent` Percent) — override per pakej
- `users` (child `Travel B2B Partner User`: `user` Link User wajib, `access_level` Select View/Docs/Full, default Full) — staf partner; sumber kewibadaan B2B (bukan role global)

### Booking (`booking.json`) — field baru
- `b2b_partner` (Link Travel B2B Partner, search_index)
- `end_customer` (Link Customer, search_index)
- Kemas kini description `booking_channel` (B2B bukan lagi "fasa hadapan")
- `cust_email` kekal = snapshot email end-customer (contact traveller); email partner diambil dari Contact `customer` partner

## 2. Harga net (deducted price) — `booking_engine.py` + `so_helpers.py`

Dalam `confirm_booking()` (`booking_engine.py:63`), bila `booking_actor["channel"] == "B2B"`:

1. **Pemilihan customer bertukar** (kawasan `booking_engine.py:166` & `:517-551`):
   - `partner_customer` = `B2B Partner.customer` → jadi `Booking.customer` dan customer SO
   - `_create_customer(billing)` tetap dijalankan untuk end-customer → disimpan sebagai `Booking.end_customer` (end customer dapat User portal + emel set-password seperti biasa melalui `_ensure_portal_user`)
2. **Diskaun B2B** selepas `_build_so_items` (sebelum voucher/referral): baris SO negatif `{"item_name": "B2B Discount (<partner>)", "rate": -(retail × pct/100)}`. Peratus = override pakej jika ada, else `default_discount_percent`.
3. **Voucher & affiliate code DILARANG** untuk saluran B2B (backend throw jika dibekalkan; frontend sembunyikan medan) — elak stacking diskaun atas harga kontrak.
4. Deposit/payment method/Stripe/manual transfer: **tiada perubahan** (pilihan anda: sama macam retail) — semuanya beroperasi atas SO partner secara automatik.
5. `_resolve_booking_actor()` (`_helpers.py:194`) dilanjut: semak dulu `Travel B2B Partner User` (user aktif, partner Active) → pulang `{channel: "B2B", partner, access_level, ...}`; role-based Staff/Affiliate kekal seperti sedia ada.

## 3. Portal — pemisahan harga & akses

### `portal_booking.py`
- `_managed_booking_names` (`:55`): tambah booking `booking_channel="B2B"` yang `b2b_partner` termasuk dalam senarai partner user tersebut (query child table). Staf partner nampak **semua** booking partner-nya, bukan hanya booking sendiri.
- `_booking_accessible` (`:100`): tambah cabang `booking.end_customer == customer_name`.
- `_booking_action_allowed` (`:125`): end-customer B2B → dibenarkan tindakan tahap **Docs sahaja** (dokumen/traveller); **Full (bayaran) sentiasa dinafikan**.
- Helper baru `_price_hidden_for(booking, customer_name)` → True bila viewer ialah end_customer booking B2B.
- `get_booking_data` (`:160`): bila `_price_hidden_for` — buang `payment.so`, `payment.so_list`, `payment_status`, `prog_payment`, jumlah addon; tambah flag `price_hidden: true`. Data trip/status/reservation/dokumen kekal.
- `get_bookings_list` (`:643`) & `get_on_behalf_bookings_list` (`:739`): strip `billed/paid/balance/payment_status` untuk booking B2B yang dilihat end-customer; untuk partner staff papar harga net seperti biasa + `end_customer_name` diambil dari `Booking.end_customer`.

### `portal_payment.py` / `addon_manager.py`
- `get_booking_so_payments`, `create_payment_request`, `submit_manual_payment`, `get_document_pdf`: end-customer B2B **automatik dinafikan** sebab SO customer = partner (bukan dia) dan bukan dalam managed set — sahkan dengan ujian, tanpa ubah logik.
- `get_available_addons`: untuk end-customer B2B, kembalikan senarai **tanpa `unit_price`** dan flag `can_checkout: false`; `checkout_addons` dinafikan bagi end-customer B2B (addon ditempah oleh staf partner, SO addon ikut `booking.customer` = partner — sedia berfungsi).

### Frontend (`public/js/`, `templates/`)
- `traveller_detail.js` / `traveller_list.js`: hormati flag `price_hidden` — sembunyikan kad harga/baki, papar notis "Bilikan diuruskan oleh agen anda".
- `traveller_billing.js` / `traveller_tx.js`: untuk end-customer B2B, halaman billing menunjukkan notis (server dah menafikan data).
- `booknow.js` + `www/booknow.py`: mod B2B — banner "Tempahan bagi pihak pelanggan — bil kepada <partner>", borang billing = data end-customer, sembunyikan medan voucher/affiliate.

## 4. Emel / pemakluman (`email_service.py`)

- `_booking_email_context` (`:125`): parameter `include_prices`; untuk booking B2B, email = contact partner.
- `_send_status_email` (`:167`): untuk booking B2B hantar **dua emel**:
  1. Kepada **partner** (contact `Booking.customer`) — template sedia ada, penuh dengan harga
  2. Kepada **end customer** (`Booking.cust_email`) — template varian traveller baru ("Booking <Status> (Traveller)", 5 template dicipta dalam `install.py`/patch, ikut corak sedia ada) **tanpa `total_fmt`/`amount_paid_fmt`/`payment_status`**, dengan nota "urusan bayaran diuruskan oleh agen anda"
- `_send_receipt_email` (`:250`): **tiada perubahan diperlukan** — resit mengikut `PE.party` = partner, jadi automatik ke partner sahaja.
- `_recompute_booking_status` (Accepted), `on_booking_update` (Processing/Confirmed), `mark_completed_trips` (Completed): semua melalui `_send_status_email` — perubahan di atas meliputi kesemua trigger.

## 6. Fasa 2 (direkodkan, tidak dilaksana)
Terma kredit/deposit % per partner, penyata bulanan partner, laporan margin (`pre_discount_total` vs net), diskaun per kategori bilik, self-signup portal partner.

## 7. Ujian penerimaan
1. B2B tempah via wizard → SO customer = partner, ada baris "B2B Discount", `Booking.end_customer` terisi, deposit sama macam retail.
2. End customer log masuk portal → tiada angka di senarai/detail/addon/transaksi; boleh muat naik dokumen; emel status diterima TANPA harga.
3. Partner staff log masuk → nampak semua booking partner (bukan hanya milik sendiri), boleh bayar/resit/invois ikut access level.
4. Emel resit/invois hanya ke partner; auto-invoice atas full payment dibilkan kepada partner.
5. Regresi: booking Direct biasa & on-behalf staff/affiliate berjalan seperti sedia ada.
