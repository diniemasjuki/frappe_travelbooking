# Pelan Restructure Traveller Portal — Multi-Page Architecture

## Keputusan Design (dari user)
- Booking Detail = **3 page berasingan** (Info / Traveller / Billing)
- Profile = **email read-only v1**, phone/password/data-request editable
- PDPA = **penuh**: privacy notice + consent log + data rights

## Struktur Fail Baharu (Frappe www routing)

```
www/traveller_portal/                    → /traveller_portal/*
  _guard.py            → shared server-side auth guard (bukan page)
  index.html/.py       → Login (login/magic/forgot/account-issue/payment-result dihalakan semula ke sini atau ke page berkaitan)
  bookings.html/.py    → My Bookings (DEFAULT selepas login)
  booking-info.html/.py        → ?ref=RC123
  booking-traveller.html/.py   → ?ref=RC123
  booking-billing.html/.py     → ?ref=RC123
  transactions.html/.py → My Transactions (+ payment-result selepas Stripe)
  profile.html/.py      → Profile
  privacy.html/.py      → Privacy Notice (PDPA)
```

`www/traveller_portal.html` (SPA lama) dihapus — skrin-skrinnya diagihkan ke page baharu. Emel lama yang paut ke `/traveller_portal` kekal berfungsi: `index.py` auto-redirect ke `/traveller_portal/bookings` bila session valid.

**Server-side guard** (kelemahan client-only auth dibaiki): setiap page `.py` semak session server-side — Guest → redirect index; tanpa Customer link → skrin account-issue.

## Backend

### Baharu
1. **`api/portal_booking.py` → `get_bookings_list()`**: per booking — booking_number, trip_name, group_name, dep/ret dates, booking_status, payment_status, total_slots, filled_count, grand_total, advance_paid, balance, currency+symbol. Grouping (Upcoming/Future/Past) di-client ikut tarikh.
2. **`api/portal_profile.py`** (baharu):
   - `get_profile()` — email (read-only), nama, phone
   - `update_phone(phone)` — update Contact Phone primary, validate phonenumbers
   - `change_password(old, new)` — verify `frappe.auth.check_password`, update User, min 8 char
   - `request_data_action(action, details)` — PDPA rights: create ToDo High utk admin
3. **Print Format "Rarecation Proforma Invoice"** (doc_type Sales Order, Jinja) — label jelas "PROFORMA — NOT A TAX INVOICE", item table, totals, booking ref, payment terms. Ditambah ke `install.py` + fungsi idempotent dalam `maintenance.py` utk site sedia ada.

### Extended
4. **`get_document_pdf()`** — benarkan doctype "Sales Order" (ownership check `so.customer`, docstatus 0/1, format proforma). Constant `PRINT_FORMAT_PROFORMA` dalam `constants.py`.
5. **`save_booking_traveller()`** — param baharu `pdpa_consent: bool`; wajib True, lain throw. Consent direkod sebagai **Comment** (doctype core — TIADA perubahan DocType JSON) sekali sahaja per Traveller.
6. **Redirect updates**: `checkout.js` returnUrl portal → `/traveller_portal/transactions`; `login_via_portal_key` + `get_google_login_url` default → `/traveller_portal/bookings`.

## Kandungan Page Penting

**bookings**: "Upcoming Trip" (1 card besar + countdown hari) / "Future Trips" / "Past Triks" (collapsed). Card: trip, dates (format "3 Sep 2026"), ref, travellers X/Y, status badges, billed/paid/balance, progress bar, CTA. Cancelled = locked card. Empty state + CTA "New Trip Booking".

**booking-traveller**: slot list per cabin → wizard recall (sedia ada: IC+passport+nama fuzzy) → form 4 panel + **consent checkbox** (link ke /privacy). Validation inline per-field + focus ke error pertama (ganti 12 alert chain).

**profile**: card account (email read-only + nota "hubungi kami"), phone form, password form (old/new/confirm), seksyen PDPA: link privacy + butang request correction/deletion.

**privacy**: notice PDPA lengkap (apa dikumpul, tujuan, perkongsian, retensi, hak, kontak) — placeholder ditanda untuk review lawyer.
